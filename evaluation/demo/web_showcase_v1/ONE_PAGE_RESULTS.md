# 核心实验结论与失败案例

## 正式结论：ResearchBench-Frozen v1.0

口径：35 题 × 3 次；同一道题先聚合，再以 35 道题为独立单位做配对 Bootstrap。

| 指标 | Fixed Harness | Dynamic Swarm | 配对结论 |
|---|---:|---:|---|
| 综合质量 | 99.68% | 99.55% | -0.13 pp，95% CI [-0.34, +0.07]，差异不显著 |
| Worker 调用 | 11.56 | 9.67 | 降低 16.39%，95% CI [10.39%, 22.13%] |
| LLM 调用 | 7.60 | 7.02 | 降低 7.64%，CI 包含 0 |
| 估算 Token | 14799 | 13596 | 降低 8.12%，CI 包含 0 |
| 平均延迟 | 26.15s | 24.72s | 降低 5.45%，CI 包含 0 |
| 估算成本 | $0.009098 | $0.008453 | 降低 7.09%，CI 包含 0 |

可信表述：Dynamic Swarm 在质量差异不显著的情况下显著减少 Worker 调用；其余效率指标方向有利，
但置信区间仍包含 0，不能写成已证明的稳定提升。

## 正式结论：ResearchBench-Adversarial

相同 35 题 × 3 次、模型与统计口径下，确定性安全补丁将 Structured Patch 的故障修复率从
86.43% 提升到 99.29%，提升 12.86 pp，95% CI [+10.00, +15.71] pp；事实准确率达到 100%，
幻觉率为 0，干净事实和引用保留率均为 100%。

## 真实 Web 单次演示

这不是统计基准，只证明最新代码能在开放 Web 上走通完整链路：

- 8 节点 DAG，5 类角色，12 次 Worker 调用。
- 104 个候选中保留 52、淘汰 52，所有淘汰都有原因 Trace。
- Claim 支持率 97.56%，引用覆盖率 98.78%；第二轮 Red Review 通过。
- 8 个已应用 Patch：DELETE 1、MODIFY 7、整篇重写 0；另有 1 个目标不唯一的 Patch 被拒绝。
- 最终复用 80 条未修改 Claim 的判断，并以 `review_passed` 停止。

## 真实失败案例

1. **演示直接发现 Claim 原子化缺陷**：首次运行把同一行中带引用的多个中文句子合并成一个复合 Claim，
   导致一个已支持子句可能让日期限定连带通过。修复分句规则并增加回归测试后，同一问题复跑时 Claim 数从
   41 增加到 90，审查粒度恢复到句子级；旧运行 SHA 保留在事故记录中，不作为最终报告。
2. **定向检索仍会发生语义漂移**：Planner 的“迁移建议”节点曾检索到通用数据迁移页面。这些结果没有进入
   最终引用，但说明仅靠 Query 改写和相关性评分不能完全解决语义漂移，仍需要 Evidence Verifier 和引用门禁。
3. **Patch 可以被拒绝**：一个自动补丁因 `claim_target_not_unique` 被拒绝。系统没有猜测应修改哪个重复文本，
   而是保留缺口；这牺牲了表面完成率，但避免误改其他正确 Claim。
4. **证据缺口而非完整成功**：最终 82 条可审查 Claim 中有 1 条部分支持、1 条无引用，状态为
   `completed_with_evidence_gaps`。Red Review 通过不等于所有 Claim 都有完整证据，最终状态仍由硬门禁决定。
5. **首次运行暴露了预算边界**：修复前运行四轮后触发 `review_budget_exhausted`，并生成 Fixed 候选；Fixed
   虽然引用覆盖率 100%，但有 22 个阻塞问题，最终仍选择 Dynamic。这说明单看引用覆盖率会选错报告。
6. **开放 Web 结果不稳定**：同一问题、同一预算的两次运行分别用了 18 和 12 次 Worker 调用。原因包括搜索
   索引结果和第一轮报告不同；因此 Live 用于端到端验收，不能替代 Frozen 的配对统计。

## 面试时不要夸大的内容

- Live 单次运行不能证明平均质量提升。
- Token 和美元成本是按固定费率估算，不等于供应商账单。
- Frozen 单题证据有限，主要用于隔离编排差异，不代表开放 Web 的完整召回能力。
- Dynamic 的综合质量没有显著优于 Fixed；项目价值在于质量护栏下的资源自适应，而不是“Agent 越多越好”。
